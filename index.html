Behind the scenes

Built in the open, bugs and all

🥚

The Egg is real geometry

Every character, weapon, and prop is procedurally modeled and generated headlessly - no purchased assets, no image-gen tool involved.

👻

The "holo" ramp bug

A build piece looked see-through from one angle only. Root cause: an engine quirk in how anchors resolve before a node's first frame - not a missing mesh face.

🔌

Multiplayer, tested for real

Two separate game processes, hosting and joining each other on the same machine, stood in for two real players - and caught two genuine bugs neither code review would have.

🎧

Even the sound is generated

Every sound effect is synthesized in code at runtime, not a sample library - the same philosophy as the visuals.

🖱️

The mouse that wouldn't come back

For a while, finishing a match left your cursor invisible and locked in the menu - found and fixed by tracing exactly one line of engine state across three screens.

📈

Just shipped: the 3-ability rework

Every Egg went from 1 ability slot to 3, plus a real numbers pass (health, ability damage, passive percentages) across the entire roster - this page gets rebuilt every time a real milestone ships.

Honestly, where this build actually stands: this is a v0.1 playable prototype, not a finished game.
  • All 30 Eggs have 3 real, working ability slots each with real counterplay — get them from Egg Crates, starting with one free the moment you finish the tutorial.
  • Real matchmaking exists in the code (auto-search for other players for 15s before filling the rest with bots) but needs an always-on relay server that isn't deployed publicly yet — right now every match runs solo against bots. LAN multiplayer (Friends → Host/Join) is a separate, working same-network option.
  • The browser build runs on WebGL (Compatibility rendering) — a couple of visual effects present on desktop don't render there.
  • No image-generation tool was used anywhere — every visual is either procedural code or a real Blender model in this repo.
